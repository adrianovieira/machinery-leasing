== 2. Escopo e Objetivos da Implementação

1. **GitHub Actions Workflow (`.github/workflows/ci.yml`)**:
   - Disparo em `push` e `pull_request` nas branches `main` e `develop`.
   - **Job 1: Lint & Static Analysis**: Executa `ruff check` e `ruff format --check`.
   - **Job 2: Contract Validation**: Executa `pytest src/tests/contract/`.
   - **Job 3: Automated Tests**:
     * Inicia MySQL 8.0 via service container com health check.
     * Instala dependências com cache de Pipenv.
     * Aplica migrations via Alembic (`pipenv run alembic upgrade head`).
     * Executa suíte completa (`pytest --cov=src/app --cov-report=xml`).
   - **Job 4: Dependency & Security Check**: Executa `pipenv check`.

2. **GitLab CI Pipeline (`.gitlab-ci.yml`)**:
   - Definição dos stages: `lint`, `contract`, `test`, `security`.
   - Execução com imagem base `python:3.11-slim`.
   - Configuração de serviço MySQL 8.0 (`services: [mysql:8.0]`).
   - Coleta de relatórios JUnit (`artifacts:reports:junit`) e cobertura de código (`coverage: '/TOTAL.*\s+(\d+%)$/'`).

3. **Validação e Simulação Local**:
   - Teste local dos comandos dos pipelines via `pipenv run` e verificação das variáveis de ambiente de CI.

== 3. Roteiro Passo a Passo de Execução

=== Passo 1: Criação do Workflow GitHub Actions
- Criar o diretório `.github/workflows/` e o arquivo `.github/workflows/ci.yml`.
- Configurar jobs modulares (Lint, Contract, Test, Security) com caching e service containers.

=== Passo 2: Criação do Pipeline GitLab CI
- Criar o arquivo `.gitlab-ci.yml` na raiz do repositório.
- Estruturar jobs correspondentes garantindo compatibilidade com GitLab Runners e GitLab Services.

=== Passo 3: Verificação de Configurações e Variáveis de Ambiente
- Garantir que parâmetros de conexão com MySQL em CI (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`) estejam devidamente alinhados aos scripts de teste e `alembic.ini`.

=== Passo 4: Validação Estática e Commits
- Executar `ruff check --fix` e `ruff format`.
- Formular mensagem de commit estruturada segundo o padrão Conventional Commits em pt-BR e solicitar aprovação prévia.
